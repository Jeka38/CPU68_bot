# CPU Evolution Bot

Telegram-бот для групп: считает обычные сообщения участников, присваивает CPU-ранги и отправляет карточки ранга в стиле Pip-Boy. База данных SQLite хранится вне контейнера.

## Быстрый запуск в Docker

Требования: Docker и Docker Compose (плагин `docker compose`).

1. Клонируйте/скопируйте проект на сервер и подготовьте конфиг:
   ```bash
   cp .env.example .env
   ```
2. Откройте `.env` и укажите минимум:
   - `BOT_TOKEN` — токен от @BotFather
   - `ADMIN_IDS` — Telegram ID админов (через запятую)
3. Соберите и запустите:
   ```bash
   docker compose up -d --build
   ```
4. Проверьте работу:
   ```bash
   docker compose ps
   docker compose logs -f
   ```

Остановка:
```bash
docker compose down
```

Обновление (после изменения кода или `.env`):
```bash
docker compose up -d --build
```

## Docker: как это работает

- Сервис: `bot` (образ `cpu-evolution-bot:latest`, контейнер `cpu-evolution-bot`).
- Запуск: `python bot.py bot`.
- Автозапуск: `restart: unless-stopped` — контейнер поднимется после сбоя и после перезагрузки сервера, если Docker включён в автозагрузке (`sudo systemctl enable --now docker` на Linux).
- Данные: хост-папка `./data` монтируется в `/data`; база — `./data/users.db` (`DB_PATH=/data/users.db` задан в compose и переопределяет `.env`). Пересборка/обновление контейнера статистику не удаляет.
- Конфиг: `.env` передаётся через `env_file` и не попадает в образ.
- Изоляция: `read_only: true`, `tmpfs` для `/tmp`, `cap_drop: ALL`, `no-new-privileges`, лимиты `mem_limit: 512m` и `pids_limit: 256`, ротация логов (`10m` × 3). Единственная постоянная запись — в `./data`.
- Необязательный non-root режим: создайте каталог и раскомментируйте `user: "10001:10001"` в `docker-compose.yml`:
  ```bash
  mkdir -p data
  sudo chown -R 10001:10001 data
  docker compose up -d
  ```
- Запускайте только один экземпляр бота на один токен/базу.

## Конфигурация (`.env`)

| Переменная | Описание |
| --- | --- |
| `BOT_TOKEN` | Токен бота от @BotFather (обязательно). |
| `ADMIN_IDS` | Telegram ID админов для `/a*`/админ-команд, через запятую. |
| `LANGUAGE` | Язык интерфейса: `ru` (по умолчанию) или `en` (`locales/`). |
| `ERROR_REPORT_IDS` | Куда слать отчёты об ошибках в ЛС; пусто = `ADMIN_IDS`. |
| `ERROR_NOTIFY_COOLDOWN_SECONDS` | Пауза между одинаковыми отчётами (по умолчанию 300). |
| `ALLOWED_CHAT_IDS` | Первичное заполнение белого списка групп (отрицательные ID, через запятую). Применяется один раз при первом запуске; далее список хранится в БД и управляется `/agroup`. Пусто — бот не обслуживает группы, пока не добавлены через `/agroup`. |
| `MESSAGE_COOLDOWN_SECONDS` | Кулдаун учёта сообщений на пользователя в чате (по умолчанию 2). |
| `COMMAND_COOLDOWN_SECONDS` | Кулдаун публичных команд на пользователя в чате (по умолчанию 3). |
| `DB_PATH` | Путь к SQLite для локального запуска (по умолчанию `users.db` рядом с `bot.py`). В Docker переопределяется на `/data/users.db`. |

## Подключение бота в Telegram

1. Добавьте бота в группу.
2. В @BotFather выполните `/setprivacy`, выберите бота и нажмите `Disable`.
3. Удалите бота из группы и добавьте снова.
4. Права администратора в группе боту не нужны (он должен быть участником).
5. Активируйте группу в белом списке: админ (`ADMIN_IDS`) отправляет в группе `/agroup add` (или в ЛС боту `/agroup add -100...`).

Без добавления в белый список бот не считает сообщения и не отвечает на публичные команды в группе. Админ-команды и `/id` доступны и в неактивированной группе, чтобы можно было её добавить.

## Команды

Пользовательские (в группе):
- `/profile` — карточка ранга (своего или участника, если ответить на его сообщение); в подписи также следующий ранг/прогресс.
- `/user` — статистика участника (себя или ответом на сообщение).
- `/ranks` — список рангов.
- `/top` — топ-10 группы.
- `/id` — Chat ID и User ID.
- `/help` — справка.

Админские (только для `ADMIN_IDS`, список показывается в ЛС с ботом):
- `/admin` — справка и ваш Telegram ID.
- `/asetrank N` — выставить ранг N (список — `/ranks`); можно ответом на сообщение, иначе с `user_id` (в ЛС: `<chat_id> <user_id> N`).
- `/areset confirm` — сбросить прогресс участника.
- `/agroup add|del|list` — управление белым списком групп.

Сообщения, отправленные до добавления бота/отключения Privacy Mode, задним числом не учитываются. Первое увиденное сообщение пользователя в чате регистрирует его, но не засчитывается (счёт со второго); никнейм обновляется при последующих сообщениях.

## Данные, бэкап и обслуживание

- База: `./data/users.db` на хосте (статистика и таблица `allowed_chats`). Не удаляйте и не коммитьте её.
- Бэкап: скопируйте `./data/users.db` (лучше при остановленном контейнере). Не храните SQLite на сетевой ФС (WAL).
- Чтобы бот мог присылать отчёты об ошибках в ЛС, админ должен хотя бы раз нажать `/start` в диалоге с ботом.
- Логи: `docker compose logs -f` (файловая ротация настроена в compose).

## Локальный запуск без Docker (опционально)

```cmd
py -m pip install -r requirements.txt
copy .env.example .env
py bot.py bot
```

Для локального администрирования доступна консоль: `py bot.py console`.

## Примечания

- Ранг повышается каждые 100 сообщений (17 рангов: Intel 286 → Threadripper, далее Beyond Threadripper). Ранги — `ranks.py` (`RANKS`), порог — `MESSAGES_PER_RANK` в `bot.py`, стили/отрисовка — `RANK_STYLES` и функции карточек в `bot.py` (держите в том же порядке, что и `RANKS`).
- Карточки генерируются локально через Pillow (Pip-Boy стиль), без внешних картинок.
- Тексты интерфейса — `locales/ru.py`, `locales/en.py` (ключи должны совпадать), язык — `LANGUAGE` в `.env`.
