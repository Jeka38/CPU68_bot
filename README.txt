# CPU Evolution Bot

## Установка (Windows)

1. Установите Python 3.10+ с https://www.python.org/downloads/
   Во время установки включите `Add Python to PATH`.
2. Распакуйте архив в отдельную папку.
3. Откройте CMD в этой папке.
4. Выполните:
   ```cmd
   py -m pip install -r requirements.txt
   ```
5. Переименуйте `.env.example` в `.env` и вставьте токен от @BotFather.
6. Запустите:
   ```cmd
   py bot.py
   ```

## Запуск в Docker (рекомендуется для сервера)

Нужен установленный Docker с Docker Compose.

1. Скопируйте проект на сервер и создайте `.env`:
   ```bash
   cp .env.example .env
   ```
   Заполните `BOT_TOKEN` и `ADMIN_IDS`. При необходимости укажите
   `ERROR_REPORT_IDS` (куда присылать ошибки) — если пусто, используются
   `ADMIN_IDS`.
2. Соберите и запустите контейнер:
   ```bash
   docker compose up -d --build
   ```
3. Проверьте логи:
   ```bash
   docker compose logs -f
   ```

База данных хранится **вне контейнера**: каталог `./data` на хосте монтируется
в `/data`, файл базы — `./data/users.db`. При пересборке и обновлении контейнера
статистика сохраняется.

Автозапуск после перезапуска сервера обеспечивает `restart: unless-stopped`.
Дополнительно Docker должен запускаться при загрузке системы:

- Linux: `sudo systemctl enable --now docker`
- Windows/macOS: включите автозапуск Docker Desktop при входе в систему.

В `docker-compose.yml` уже включена базовая изоляция: контейнер работает с
read-only rootfs, без Linux capabilities (`cap_drop: ALL`), с
`no-new-privileges`, лимитами памяти/процессов и отдельным `tmpfs` для `/tmp`.
Единственное место записи — смонтированный `./data`.

Для более строгой изоляции можно запускать бота не от root. Создайте каталог
данных с нужным владельцем и раскомментируйте `user:` в `docker-compose.yml`:

```bash
mkdir -p data
sudo chown -R 10001:10001 data
```

Обновление после изменения кода или `.env`:
```bash
docker compose up -d --build
```

Остановка:
```bash
docker compose down
```

## Telegram

- Добавьте бота в группу.
- В @BotFather выполните `/setprivacy`, выберите бота и нажмите `Disable`.
- Удалите бота из группы и добавьте снова.
- Для подсчёта сообщений боту не нужны права администратора.
- Бот должен оставаться участником группы, чтобы получать сообщения и отправлять карточки.
- Добавьте группу в белый список: отправьте `/agroup add` в самой группе от имени
  админа (ID из `ADMIN_IDS`). Без этого бот не считает сообщения и не отвечает на
  публичные команды в группе.

Команды:
- `/profile` — карточка своего процессорного ранга.
- Ответьте на сообщение участника командой `/profile` — карточка этого участника.
- `/rank` — текстовая информация о ранге.
- `/user` — статистика участника (ответом на сообщение — другого участника).
- `/ranks` — список рангов.
- `/top` — топ-10 группы.
- `/id` — показывает Chat ID группы и User ID (в ответ на сообщение — ID другого участника).
- `/help` — список команд.

## Админка в Telegram

Управление доступно прямо в Telegram и только для Telegram ID из `ADMIN_IDS`.

1. Узнайте свой user ID командой `/id` в группе.
2. Впишите ID в `.env` (несколько — через запятую):
   ```
   ADMIN_IDS=123456789,987654321
   ```
3. Перезапустите бота: `py bot.py` локально или `docker compose up -d`
   на сервере.

Админ-команды:
- `/admin` — справка и ваш Telegram ID.
- `/aadd N` — добавить N сообщений.
- `/asetrank N` — выставить ранг номер N (список — `/ranks`).
- `/areset confirm` — сбросить прогресс (в ответ на сообщение или с user ID;
  без `confirm` только предупреждение).
- `/agroup add|del|list` — белый список групп (подробнее ниже).

Пользовательские команды `/user`, `/ranks`, `/top` доступны всем в группе.

Как указать участника:
- В группе ответьте командой на сообщение участника и передайте только параметры:
  `/aadd 150`.
- Без ответа первым параметром укажите user ID: `/aadd 123456789 150`.
- В личке бота сначала chat ID группы, затем user ID:
  `/aadd -1001234567890 123456789 150`.

Карточка повышения отправляется автоматически, если `/aadd` или `/asetrank`
подняли ранг. Консольный режим (`py bot.py console`) остался как локальный
резервный инструмент.

Отображение админ-команд: список `/a*` видят только админы и только в личном
чате с ботом. В группе `/help` и `/admin` не показывают админские команды.

## Белый список групп

Бот обслуживает только группы из белого списка. Пока список пуст, в группах не
работают ни подсчёт сообщений, ни публичные команды. Админ-команды и `/id`
доступны в любом чате — поэтому группу можно добавить прямо из неё.

- `/agroup add` — добавить текущую группу.
- `/agroup del` — удалить текущую группу.
- `/agroup list` — показать белый список.
- В личке бота: `/agroup add -1001234567890`, `/agroup del -1001234567890`.

Если в неактивной группе вызвать публичную команду, бот ответит, что чат не
активирован (не чаще кулдауна команд).

`ALLOWED_CHAT_IDS` в `.env` — необязательное первичное заполнение списка при самом
первом запуске (ID групп отрицательные, через запятую). Дальше список хранится в
базе (`allowed_chats`) и управляется командами `/agroup`; при следующих запусках
переменная игнорируется, поэтому удалённые группы не возвращаются. Пустое значение
ничего не добавляет: без `/agroup add` бот останется выключенным для всех групп.

## Отчёты об ошибках

- Необработанные ошибки команд и сообщений бот отправляет в личные сообщения
  всем ID из `ERROR_REPORT_IDS` (если переменная пуста — из `ADMIN_IDS`).
- В отчёте: время, тип обновления, chat_id, user_id, имя, команда (если ошибка
  произошла на команде) и полный traceback. Обычный текст сообщений не
  пересылается.
- Критические ошибки polling тоже отправляются админам, после чего бот
  перезапускает polling с увеличивающейся паузой (до 5 минут) и не роняет
  контейнер.
- Одинаковые ошибки не чаще одного раза в `ERROR_NOTIFY_COOLDOWN_SECONDS` секунд
  (по умолчанию 300), чтобы не заспамить личку.
- Чтобы Telegram мог доставить сообщение, админ должен хотя бы раз нажать
  `/start` в личном чате с ботом. Если это не сделано, ошибка пишется в лог
  (`docker compose logs -f`).

## Антиспам

- Сообщение учитывается не чаще одного раза в `MESSAGE_COOLDOWN_SECONDS` секунд
  на участника в каждом чате (по умолчанию 2).
- Публичные команды имеют общий кулдаун `COMMAND_COOLDOWN_SECONDS` на участника
  в чате (по умолчанию 3), чтобы нельзя было спамить карточками.
- Оба значения задаются в `.env`; `0` отключает соответствующую защиту.

## Безопасность

- **Токен и секреты.** Токен бота хранится только в `.env`, который исключён
  через `.gitignore` и `.dockerignore`. Токен и строки, похожие на токен,
  вырезаются из логов и отчётов об ошибках (`<bot-token>`), чтобы прокси или
  HTML-страница с URL запроса не скомпрометировали его.
- **SQL.** Все запросы к SQLite выполняются с параметрами `?`; пользовательский
  ввод (имена, ID, лимиты) не подставляется в текст SQL. Не заменяйте параметры
  f-строками при доработке.
- **Лимиты ввода.** Админ-числа проверяются на диапазон signed 64-bit, счётчик
  сообщений ограничен `MAX_MESSAGES` (10 000 000). Это защищает от `OverflowError`
  SQLite и абсурдных значений.
- **Лимиты вывода.** Длинные списки (`/top`, `/ranks`, `/agroup list`) обрезаются
  до безопасной длины, а имена очищаются от управляющих/невидимых символов и
  экранируются — сообщение не превысит лимит Telegram 4096 символов и не сломает
  HTML-разметку.
- **Антиспам.** Кулдауны на сообщения и публичные команды ограничивают флуд,
  в том числе генерацию карточек.
- **Доступ.** Админ-команды проверяют Telegram user ID из `ADMIN_IDS`; список
  админ-команд показывается только админу в личке. Белый список групп строгий:
  группы вне `allowed_chats` не обслуживаются.
- **База данных.** В базе есть имена и статистика участников. Каталог `./data`
  не коммитится; на сервере ограничьте права (например, `chmod 700 data`) и
  делайте бэкапы. Не храните базу на сетевой ФС — SQLite WAL этого не любит.
- **Один экземпляр.** Не запускайте два процесса с одним токеном: Telegram
  вернёт конфликт polling, а два контейнера с одной базой могут конфликтовать.
- **Зависимости.** Версии в `requirements.txt` ограничены снизу и сверху;
  обновляйте их осознанно и проверяйте известные уязвимости.

## Консольные тесты

Запустите `py bot.py`, затем выберите пункт 2, или сразу:
```cmd
py bot.py console
```

В консоли доступны поиск пользователя, добавление сообщений, установка ранга,
сброс прогресса, просмотр топа и отправка тестовой карточки.

Для консольных операций понадобятся:
- Chat ID группы (обычно отрицательное число, например -100...)
- Telegram user ID участника (положительное число)

Как узнать ID:
- Добавьте временно в группу бота, который показывает ID чата/пользователя,
  либо используйте собственного ID-бота.
- Также можно получить chat_id из логов обновлений своего бота; user_id можно
  получить через команду /id в группе (ответьте на сообщение участника командой /id, чтобы узнать его ID).

## Важно

- База `users.db` создаётся автоматически рядом с `bot.py`. Путь можно изменить
  переменной `DB_PATH`; в Docker используется `/data/users.db`, то есть
  `./data/users.db` на хосте. В базе хранятся статистика и белый список групп
  (таблица `allowed_chats`).
- Не удаляйте файл базы, если хотите сохранить статистику. Для бэкапа скопируйте
  `./data/users.db` (лучше при остановленном контейнере).
- Не публикуйте `.env` и токен бота.
- Сообщения, отправленные до добавления бота/отключения Privacy Mode, задним числом не учитываются.
- Текущая версия считает обычные сообщения пользователей в группах; команды, ботов и сообщения каналов не считает.
- Первое увиденное сообщение пользователя в чате не засчитывается (пользователь регистрируется в базе), счёт начинается со второго. При смене никнейма имя обновляется при последующих сообщениях.
- Ранг повышается каждые 100 сообщений. Первый ранг — Intel 286.
- Карточки генерируются автоматически локально через Pillow; отдельные картинки скачивать не нужно.
- Для каждого ранга рисуется своя карточка: палитра, форма процессора и подпись
  (286, 386, 486, Pentium, Core, Ryzen, Threadripper).
- Длинное имя на карточке переносится на 2-3 строки и при необходимости
  уменьшается шрифт; если места не хватает даже на трёх строках, остаток
  заменяется на `...`.

## Язык и тексты

- Названия процессоров лежат в `ranks.py` (список `RANKS`); порядок списка задаёт
  прогрессию рангов.
- Переводы интерфейса лежат в `locales/`: `ru.py` (по умолчанию) и `en.py`.
  Каждый файл — словарь `STRINGS`; набор ключей должен совпадать во всех языках.
- Язык выбирается в `.env`: `LANGUAGE=ru` или `LANGUAGE=en`. Если язык не найден,
  используется русский.
- Чтобы добавить язык, скопируйте `locales/ru.py` в `locales/<код>.py`, переведите
  значения и укажите `LANGUAGE=<код>`.
- Надписи на карточках тоже берутся из словаря (ключи `card_*`). Названия
  процессоров не переводятся — это имена моделей.

## Изменение рангов

Откройте `ranks.py` и измените список `RANKS`.
Требование к повышению меняется в `bot.py`: `MESSAGES_PER_RANK = 100`.
При добавлении ранга добавьте стиль в `RANK_STYLES` (в `bot.py`) в том же
порядке — иначе новый ранг будет использовать стиль Threadripper.
